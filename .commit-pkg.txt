[T5.8] Package without signing on restricted hosts, and report the NFR-02 miss

Adds a packaging path that works on a machine where the default
`electron-builder --win` cannot:

- `build/icon.ico` and `build/icon.png` are now generated from code by
  `scripts/make-icon.mjs` (hand-built ICO container, two PNG sizes rendered
  from the same SVG as the tray icon) instead of being checked-in binaries.
- `scripts/pack-win.mjs` (`npm run build:win:nosign`) packs with the sign
  stage disabled, stamps icon and version metadata with rcedit, then builds
  the NSIS installer from the stamped directory. It redirects
  electron-builder's download caches out of `%LOCALAPPDATA%`, exposes the
  `7za` that `7zip-bin` ships, and falls back to calling an unpacked
  `rcedit-x64.exe` directly when app-builder cannot unpack the winCodeSign
  archive for want of the Windows symlink privilege.
- `.builder.nosign.yml` extends the normal config with
  `win.signAndEditExecutable: false`; the shipped `electron-builder.yml`
  stays free of workarounds.

Also measures the non-functional budgets against the packaged binary and
records the result honestly: idle CPU is 0.018% (budget 0.3%) but resident
memory is 393.7 MB across four processes (budget 220 MB). The README
performance table shows the failing row, and DECISIONS.md D-019 explains
why reclaiming the renderer while the window is hidden is the real fix and
why it is left as a follow-up.
